# vitals — 左下角透明生命体征跑马灯

屏幕左下角、任务栏正上方，一条 **620×30 像素的小字滚动条**，实时跳动的生命指标。
真·透明背景、无边框、置顶、可拖动。纯 C (C99) + Win32 GDI，单文件，零第三方依赖。

```
生命体征监测  //  HR 64  RR 14  SpO2 98  T 36.7  BP 118/76  //  LIVER(肝功) ALT 22 ... →→→
```

## 1. 编译

双击 `build.bat`。`cl` 必须带 **`/utf-8`**（源码和 ini 里的中文是 UTF-8，不加会报 `C2001`）。

```bat
call "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat"
cl /nologo /W3 /O2 /utf-8 vitals.c /link /SUBSYSTEM:WINDOWS /ENTRY:wWinMainCRTStartup user32.lib gdi32.lib
```

## 2. 用法

| 操作 | 效果 |
|---|---|
| 左键拖动 | 移动位置（自动记忆） |
| 滚轮 | 调字号（不灵就用右键菜单） |
| 右键 | 字号 / 置顶 / 回到默认位置 / 重载配置 / 退出 |

改完 `vitals.ini` 后**右键 →「重新加载配置」**即刻生效，不用重启。

## 3. 配置

### 外观
```ini
font         = Consolas        ; 数字字体(等宽)
font_cjk     = Microsoft YaHei ; 汉字字体
size         = 12
opacity      = 235             ; 整体透明度, 调低更不起眼
color        = #00E5FF
glitch       = 0
align        = 1               ; 见下方"为什么不会抖"
```

> ⚠️ **中文必须有专门的字体。** Consolas 里**一个汉字字形都没有**（实测 6 个字全是 `GGI_MARK_NONEXISTING_GLYPHS`），
> 拿它渲染中文会变成一排方块。所以程序按"这段有没有 CJK 字符"自动切字体：
> 数字走 `font`，汉字走 `font_cjk`。想换中文字体改 `font_cjk` 即可（SimSun / SimHei / 等线都行）。

### 滚动
```ini
scroll = 1
width  = 620    ; 那一小条的宽度
speed  = 55     ; 像素/秒
gap    = 130    ; 每圈之间的空隙
fps    = 60     ; 帧率
interval = 100  ; 数值检查间隔, 要小于最小的 rate
```

### 模板
```ini
line = 生命体征监测 // HR @HR@  RR @RR@  BP @SBP@/@DBP@  // LIVER ALT @ALT@ ...
```
`@名字@` 取槽值，`@@` 输出字面 `@`，其它字符原样显示。

### 数值槽
```ini
;            范围         颜色      模式:步长:小数位   报警区间   报警色
slot.HR   = 62~98    | #39FF14 | walk:2         | 55~110  | #FFB300
rate.HR   = 500      ; 这个槽每 500ms 动一次
```
| 字段 | 说明 |
|---|---|
| `min~max` | 范围 |
| 颜色 | `#RRGGBB` 或 `g`绿 `c`青 `m`品红 `y`琥珀 `r`红 `w`白 |
| 模式 | `fixed` / `random` / `walk`（小幅漂移，推荐） |
| 步长 | walk 单次最大变化量 |
| 小数位 | 0~6 |
| 报警区间 / 报警色 | 超范围换色 |

### 更新节奏 `rate.名字 = 毫秒`
**不同的指标该用不同的速度**，这才像真的监护仪：

| 指标 | rate | 理由 |
|---|---|---|
| HR 心率 | 500ms | 最快，心搏级别 |
| SpO2 | 1500ms | 较快 |
| RR 呼吸、血气 pH/PaO2/PaCO2 | 2~3s | 中等 |
| T 体温、血压 | 5~20s | 慢 |
| 神经递质 DA/5-HT/NE | 15s | 慢 |
| 肝功 ALT/AST/TBIL/ALB、肾功 BUN/CREA | 60s | 几乎不动 |
| 肾功 UA | 120s | 更慢 |
| 甲功 TSH/FT3/FT4 | 300s | 基本恒定 |

## 4. 为什么要 `align = 1`

数字位数会变（`96` → `100`，`9.5` → `10.2`），如果不定宽，**整行宽度就会来回变，缓冲区里每个字的位置都在挪** —— 滚动时看起来就是"抽一下再抽回来"。

`align = 1` 时每个槽按"它可能写出的最长字符数"右对齐补空格，整行宽度**恒定**。
自检里有一项专门验这个：`vitals.exe --selftest` 会做 300 次全量刷新并统计宽度变化次数，正常是 **0**。

```bat
vitals.exe --selftest    :: 每段宽度/覆盖率/宽度恒定检查, 不会出窗口
vitals.exe --bench       :: 帧率与各段耗时, 结果写 bench.txt
```

## 6. 性能

| 项目 | 数值 |
|---|---|
| 取景（纯 memcpy） | 0.002 ms |
| 上屏 ULW | 0.056 ms |
| 每帧合计 | **0.067 ms**（16.67ms 预算的 0.4%） |
| 实跑帧率 | **60.0 fps**（不丢帧） |
| CPU | 约 1% 单核 |
| 内存 | 约 8 MB |

关键设计：
1. **两级缓冲**：`PaintLine()` 把"一整圈（文字+空隙）"预渲染成静态宽图，**只在有槽变化时重画**；滚动只做 `PaintWindow()` —— 因为整圈都在缓冲里，取景就是**纯 memcpy**（每行最多两段，环绕无缝）。
2. **缓存屏幕 DC**：`CreateDCW(L"DISPLAY")` 只建一次，不再每帧 `GetDC/ReleaseDC`。
3. **跳过重复帧**：整数偏移没变、也没数值更新时，不画、不调 ULW。
4. **高精度帧同步**：`CreateWaitableTimerEx(CREATE_WAITABLE_TIMER_HIGH_RESOLUTION)` + `MsgWaitForMultipleObjectsEx` 自建游戏式主循环，带漂移补偿。（`SetTimer` 默认粒度 15.6ms，根本跑不到 60fps。）
   建不出高精度定时器会自动退回 `WM_TIMER`。
5. **只在需要时重画**：每个槽按自己的 `rate` 更新，没有任何槽到点就不重画整行。

## 9. 字体：为什么不能"英文一个、中文一个"

### 科学的判据：中英宽度比必须是 **2:1**（全角/半角）

滚动条要"不抖"，前提是**同一段文字任何时候渲染出来都一样宽**，而且中英文能对齐。实测本机字体：

| 字体 | 汉字宽 | 数字宽 | 比值 | 有汉字字形 |
|---|---|---|---|---|
| DengXian 等线 | 18 | 9 | **2.00** ✅ | 是 |
| SimHei 黑体 | 18 | 9 | **2.00** ✅ | 是 |
| SimSun 宋体 | 18 | 9 | **2.00** ✅ | 是 |
| Microsoft YaHei | 18 | 11 | 1.64 ❌ | 是 |
| Noto Sans SC | 18 | 10 | 1.80 ❌ | 是 |
| Consolas | — | 10 | — | **否（一个汉字都没有）** |
| Cascadia Mono | — | 11 | — | **否** |

**结论：默认 `font = DengXian`（等线），`font_cjk` 留空 —— 一个字体通吃，中英风格/粗细/高度完全一致。**
（Consolas 那种"西文好看"的思路在这里是错的：它连一个汉字字形都没有，必须靠第二个字体兜底，一混就必然不统一。）

跑 `vitals.exe --selftest` 会打印**字体体检**：覆盖率 + 中英宽度比。换字体后先看这一行是不是 `2.00`。

### 想要更"原著"的味道

装一个 **Sarasa Mono SC（更纱黑体等宽）** —— 免费开源（OFL），就是为"中文 = 2 个西文宽"设计的，笔画是方块化的科技感：

> https://github.com/be5invis/Sarasa-Gothic/releases  → 下载 `SarasaMonoSC-TTF-*.7z`，解压后全选字体 → 右键"为所有用户安装"

装完把配置改成：
```ini
font     = Sarasa Mono SC
font_cjk =                 ; 留空, 它自带中文
```

### 数字对齐（`align = 1`）

数字位数会变（`96` → `100`）。早期版本用"空格补位"，**这只对纯等宽字体有效**——字体一旦不是等宽，空格和数字宽度不同，整行宽度还是会变，滚动就会抖。

现在的做法是**像素级固定格子**：每个槽按"它可能写出的最宽值"分配一个固定像素宽的格子，数字在格子里右对齐。跟字体是否等宽无关，永远恒定。
自检项 `宽度恒定` 会做 300 次全量刷新统计宽度变化次数，正常是 **0**。

## 10. 超标箭头 ↑ / ↓ 与加粗

### 箭头

`arrow = 1` 时，**每个槽后面自动跟一个箭头格子**：值超出「正常区间」就显示 ↑（偏高）或 ↓（偏低），同时数字和箭头一起变成报警色。

```
HR 48↓    SpO2  97    T 37.6↑    ALT 22
```

关键：**箭头格子永远是固定宽度**，有没有箭头整行宽度都不变 —— 否则箭头一出现一消失，滚动又会抽。

所以配置里要区分两个区间：

| | 含义 | 例子（HR） |
|---|---|---|
| **可能范围** `min~max` | 这个值能飘到的最宽范围 | `45~155` |
| **正常区间** 第 4 个字段 | 医学正常值，超出就出箭头 | `60~100` |

```ini
slot.HR = 45~155 | #39FF14 | walk:3 | 60~100 | #FF2E88
;         可能范围   颜色      步长     正常区间  报警色
```

### 频率调节 `pull`

`pull = 2` 是**回归强度（%）**：每步把数值往「正常区间中心」拉回一点，像真人的自稳机制。

| pull | 箭头出现频率 | 感觉 |
|---|---|---|
| 1 | 25% | 一半指标都在报警，太吵 |
| **2** | **11%** | **默认：随时 2~3 项超标，能看见箭头** |
| 3 | 7% | 安静 |
| 4 | 4% | 几乎全是正常的 |

自检里会打印实测频率：`箭头频率 : 10.9% 的槽处于超范围状态`。觉得箭头太少就把 `pull` 调小。

也可以单个槽覆盖：`pull.HR = 1`

### 加粗 `bolden`

```ini
bolden = 1     ; 0/1/2
```

做法是**把字形覆盖率往右再叠 1~2 遍**（fake bold），而不是去找字体的粗体face。好处：
- 任何字体都能用，不依赖它是否自带 Bold
- 小字号下不会像 GDI 合成的粗体那样糊成一团
- 强度可调（1 = 稍微粗，2 = 明显粗）

想要更粗还可以配合 `weight = 700`（前提是字体有粗体，DengXian 有）。

## 12. 实时波形小图

**右键 → 「波形小图」**（带勾选状态，切换后记住，存在 state 文件里）。配置：

```ini
wave       = 1            ; 1 = 开, 0 = 关
wave_h     = 26           ; 波形带高度(像素)
wave_type  = ecg          ; ecg 心电 / ppg 脉搏波 / resp 呼吸波
wave_color = #39FF14      ; 波形颜色
```

### 重点：波形的节律是真的跟着数据走的

`ecg` 和 `ppg` 的周期取自 **HR 槽**，`resp` 取自 **RR 槽**：

```c
g_wavePhase += (HR / 60.0) / fps;      // 每帧推进的相位
```

所以心率飘到 120 的时候，波形就真的变成 2 格/秒 —— **HR 数值和波形永远对得上**，盯着看也挑不出毛病。

### 三种波形

| 类型 | 形状 | 数据源 |
|---|---|---|
| `ecg` | P-QRS-T 五个高斯波叠加，有 R 峰、S 谷、T 波 | HR |
| `ppg` | 主峰 + 重搏波（双峰脉搏波） | HR |
| `resp` | 慢速正弦（吸气/呼气） | RR |

### 实现要点

波形**画在窗口层，不跟着文字滚动**。渲染管线现在是三段：

```
PaintLine()    整圈文字 -> 行缓冲   (只在数值变化时重画, 600ms 级)
PaintWindow()  按滚动偏移取一屏 -> 窗口缓冲   (纯 memcpy)
PaintWave()    在窗口缓冲的下方画波形   (每帧都画, 不参与滚动)
```

开波形时窗口会变高（620×25 → 620×53），默认还是贴着任务栏往上长。

波形用 620 个浮点样本的滚动缓冲，每帧左移一位、右边补新样本，相邻两点之间竖向连线，所以是连续的折线而不是散点。

### 开销

| | CPU(8秒) | 内存 |
|---|---|---|
| 波形开 | 1.37% 单核 | 9.4 MB |
| 波形关 | 1.95% 单核 | 8.8 MB |

（两者都是每帧重画、60fps，所以开销基本一样；差异在测量噪声范围内。）

## 13. v0.5 修复记录

### Bug 1（严重）：关掉波形 / 换设备之后，动画彻底卡死

**根因**：`FullReset()` 里的 `CreateFrameTimer()` 每次都重新 `CreateWaitableTimerEx()` 并覆盖 `g_hTimer`，
但主循环正卡在 `MsgWaitForMultipleObjectsEx()` 上等的还是**旧句柄**，而新句柄从来没被 `SetWaitableTimer()` 武装过 →
永远等不到下一帧信号。而关波形、换设备、改字号、重载配置**全都走 FullReset**，所以必现。

**修法**（三层保险）：
1. 帧定时器**句柄只建一次、之后复用**，绝不换句柄
2. `CreateFrameTimer()` 里重建时间基准后**立刻 `ScheduleFrame()` 重新武装**
3. 加 **500ms 看门狗**：`WM_TIMER(1)` 里发现超过 500ms 没出帧就自动重新武装

**回归测试**（脚本 `PostMessage(WM_COMMAND, ...)` 模拟点菜单，量两次截图之间的变化像素）：

| 场景 | 变化像素 / 300ms |
|---|---|
| 初始状态 | 791 |
| **关掉波形**（原来必卡死） | **755** ✅ |
| 再开回波形 | 777 ✅ |
| 点「刷新显示」 | 738 ✅ |
| **换一台监测设备** | **738** ✅ |

顺带把菜单命令抽成了 `DoCommand()` 并接上 `WM_COMMAND`，所以现在可以用脚本触发任何菜单动作：

```powershell
PostMessage($hwnd, 0x0111, [IntPtr]1009, 0)   # 1009 = 右键里的"波形小图"
```

### Bug 2：波形跟文字不同步 + 顿挫

**两个独立原因**：

1. **点采样导致尖峰闪烁**。R 波只占 0.02 个相位，一帧只采一个相位点，所以峰顶时有时无，看起来就是一跳一跳。
   → 改成**每列 8 次超采样取峰值保持**（就像真监护仪那样做 min/max 保持）。
   实测：R 波最高点 14 帧全部稳定在**同一行**，极差 **0**。

2. **速度不一致**。波形原来是固定 1px/帧（= 60px/s），而文字是配置里的 `speed`（55px/s），两者各走各的。
   → 波形也改成用 `g_cfg.speed` 推进（亚像素累加器），**文字滚一格波形也走一格，完全同步**。

### 新增：右键「刷新显示」

`IDM_REFRESH` → `FullReset()`，重新武装定时器 + 全量重绘。以后万一遇到任何画面异常，点一下就好。

## 14. 图标 / 托盘 / 设置界面

### APP 图标（代码绘制，不是 AI 生图）

`make_icon.ps1` 用 GDI+ 把图标**画**出来：圆角透明底 + 线性渐变 + 青色霓虹描边 + 绿色 ECG 折线（P-QRS-T）+ 外发光，
一次输出 **10 个尺寸**（16/20/24/32/40/48/64/96/128/256）打包成一个 `vitals.ico`。

为什么不用 AI 生成：AI 出的是位图，缩到 16×16 会糊成马赛克；代码画的是矢量，每个尺寸单独渲染，小尺寸下依然清楚。

```powershell
.\make_icon.ps1     # 重新生成 vitals.ico（改颜色/线形直接改脚本里的数组）
```

`vitals.rc` → `rc /nologo vitals.rc` → `vitals.res` → 链进 exe。所以**资源管理器里显示的就是这个图标**（已用 `ExtractIconEx` 验证 exe 内有 2 个图标资源）。

## 15. v0.6 修复记录（四个反馈问题）

### ① 设置界面里"波形开关 / 波形类型"像假的

**根因**：`wave` 这个设置被**两个地方**管着 —— `vitals.ini` 和 `vitals.state` 里的 `wave=`。
右键菜单切换时会写进 state 并记下 `g_waveOverride`，而设置界面保存时代码里有一行
`if (g_waveOverride >= 0) g_cfg.wave = g_waveOverride;` —— **又把设置界面刚改的值覆盖回去了**，所以开关看着是死的。
波形类型没效果也是因为它：波形被强制关掉了，改类型自然什么都看不见。

**修法**：
- **`vitals.ini` 成为 `wave` 的唯一来源**，state 文件不再存这个键
- 右键切换波形时直接改写 ini（`IniSetValue`），不再走覆盖值
- 删掉那行覆盖逻辑

**验证**（脚本发 `WM_LBUTTONDOWN` 点开关再点保存）：

| | 面板高度 |
|---|---|
| 起始（波形开） | 52 |
| 点开关后（未保存） | 52 |
| **点「保存并应用」后** | **26** ✅ |

`wave_type` 也验证了：点第二个选项（PPG）保存后 `vitals.ini` 里变成 `wave_type = ppg` ✅

### ② 滚动文字里的 "HR" 消失

**根因**：`AddLiteral()` 会把紧跟后面的字面文本合并进上一段以省 run 数量，
但 `@DEVICE@` 那一段的标志是 `isSlot=0`，于是 `" //  HR "` 被合并进了设备名那一段；
而 `ComposeTexts()` 对 `isText` 段是**整段覆盖**写入设备名的 —— **"HR" 被冲掉了**。

**修法**：`AddLiteral()` 不再合并进 `isText` 段。

验证：`run[2] = ' //  HR '`（56px）✅

### ③ ini 里那个模板是一行天书

**修法**：支持 **`line1` / `line2` / `line3` …** 分段写，程序会自动拼成一行。
现在 ini 里是这样，一眼能看懂，也能单独改某一组：

```ini
line1 = 生命体征监测  //  SRC: @DEVICE@
line2 = //  HR @HR@   RR @RR@   SpO2 @SPO2@   T @T@   BP @SBP@/@DBP@
line3 = //  LIVER(肝功)  ALT @ALT@  AST @AST@  TBIL @TBIL@  ALB @ALB@
line4 = //  RENAL(肾功)  BUN @BUN@  CREA @CREA@  UA @UA@
line5 = //  THYROID(甲功)  TSH @TSH@  FT3 @FT3@  FT4 @FT4@
line6 = //  ABG(血气)  pH @PH@  PaO2 @PAO2@  PaCO2 @PACO2@  HCO3 @HCO3@
line7 = //  NEURO(神经递质)  DA @DA@  5-HT @HT5@  NE @NE@
```

### ④ 弹出右键菜单 / 托盘菜单时，跑马灯暂停

**根因**：`TrackPopupMenu` 会跑一个**模态消息循环**，它只派发消息、不会回到我们的主循环，
所以主循环里 `MsgWaitForMultipleObjectsEx` 等的高精度定时器信号**一直收不到** → 动画停。
（拖窗口标题栏、拖边框也一样。）

**修法**（两步，都很关键）：
1. **dt 改成真实流逝时间**（`QueryPerformanceCounter` 测），不再用固定的 `1/fps`。
   这样"谁触发"就不重要了，推进速度永远一致。
2. **常态挂一个 16ms 的 `WM_TIMER` 兜底**。模态循环会正常派发 `WM_TIMER`，所以菜单开着也照跑。
   为避免正常时双倍推进，兜底里加了个判断：**只有当高精度定时器最近一帧没被处理时才补帧**。

**验证**：

| 场景 | 变化像素/300ms |
|---|---|
| 初始 | 983 |
| 关掉波形 | 829 ✅ |
| 再开回波形 | 876 ✅ |
| **右键菜单弹出中** | **920**（原来是 **0**）✅ |

### 附带：`--setlog`

调设置界面的时候加了个开关：`vitals.exe --setlog` 会把每次点击的**实际客户区坐标 + 命中行**写进 `setlog.txt`。
（这次就是靠它发现"测试脚本发的坐标被系统按 DPI 缩放了 1.5 倍"，程序本身没问题。）

## 16. v0.7 修复记录

### ① vitals.ini 被写成"一行天书"（严重）

**现象**：ini 打开后只有一行，后面全乱。实测文件里 **`0x0D`(CR) 出现了 24469 次**，平均每行 233 个 ——
编辑器碰到一堆裸 CR 就会把整份文件渲染成一行。

**根因**：`IniSetValue()` 用**文本模式** `_wfopen(path, L"w, ccs=UTF-8")` 写文件。
文本模式下 CRT 会把每个 `\n` 翻译成 `\r\n`，而文件里本来就是 `\r\n` → 变成 `\r\r\n`。
每保存一次多一层 CR，设置界面一次保存要调用 `IniSetValue` 约 30 次，所以攒几次就爆了。

**修法**：
- 读的时候把**行尾所有 `\r` 全部剥掉**（循环剥，不只是一个）
- 写的时候**只写 `\n`**，`\r\n` 交给 CRT 翻译
- 这样一个来回永远是 `\r\n`，反复保存不会膨胀

> ⚠️ 中途一度改成 `"wb, ccs=UTF-8"`，结果**更糟**：加了 `b` 之后 CRT 不认 `ccs` 参数了，
> 宽字符流默认按 **UTF-16LE** 写出，文件变成一堆 `x\0x\0`（42 字节里只有 21 个字符）。
> 所以**必须用文本模式**，`ccs=UTF-8` 才生效。

**验证**：连续 10 次保存 → `5453 → 5453` 字节，**零增长**；`LF=106 / CR=106 / NUL=0` 内容完好 ✅

### ② 滚动有轻微顿挫

**根因**：整数像素量化。55 px/s ÷ 60 fps = **0.9167 像素/帧**，也就是**每 12 帧就有一帧原地不动** ——
单看不出来，但眼睛对这个周期性"卡一拍"很敏感。

**修法**：加 `smooth = 1` 亚像素平滑（右键设置 → 外观 → 亚像素平滑）：

- **文字**：取景时按小数部分在相邻两列之间做**线性插值**（预乘 alpha 空间里插值是正确的），
  于是 0.9167 像素的位移会体现成"0.92 个像素的混合"，而不是"要么 0 要么 1"
- **波形**：同样用累加器的小数部分对相邻采样做**纵向插值**，波形也平滑左移

**代价**（`--bench` 实测）：

| | 关平滑 | 开平滑 |
|---|---|---|
| 取景 | 0.002 ms | **0.076 ms** |
| 每帧合计 | 0.067 ms | **0.145 ms** |
| 实跑帧率 | 60.0 fps | **60.0 fps** |

慢是慢了 38 倍，但绝对值只有 0.076 ms —— 占 16.67ms 预算的 **0.9%**，帧率依然是满的。
嫌糊或者想省 CPU，把 `smooth` 改 0 就回到纯 memcpy。

## 17. v0.8 修复：QRS 在"蹦迪"

**现象**：心电图那一下 R 尖峰一帧高、一帧矮，像在跳舞。

**根因**：上一版加"亚像素平滑"时**对波形用错了方法**。

- 文字用**线性插值**做亚像素移动是对的（文字是连续笔画，插值 ≈ 移动）
- 但 R 波只有 **1 个像素宽**。对它做**纵向线性插值**，`frac=0.5` 时画出来的高度只有峰值的**一半**
- 而 `frac` 每帧都在 0→255 之间变，于是尖峰高度就一帧满、一帧半 —— **蹦迪** ✅

**修法**：波形改用**横向 4 倍过采样 + 逐列峰值保持**：

```
采样点密度 = 像素密度 x 4          -> 位置精度 0.25 像素, 平滑
每列 = 该列 4 个采样里离基线最远的那个  -> 尖峰幅度一点都不丢
```

这才是数字示波器/监护仪的标准做法（decimation with peak-hold）。
而且**不需要插值**，所以幅度天然守恒。

顺带把波形的相位步长也改成按"速度 x 过采样倍数"算，横向速度和上面文字保持一致。

**验证**：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| R 波最高点连续 24 帧 | 上下大幅跳动 | **极差 0（全在同一行）** ✅ |
| 每帧耗时 | 0.145 ms | **0.150 ms** |
| 实跑帧率 | 60.0 fps | **60.0 fps** |

> 顺带记一笔：`smooth` 开关**只作用于文字**。波形的平滑靠过采样实现，
> 因为"对尖峰做纵向插值"在原理上就是错的 —— 插值会削掉幅度。

## 18. v0.9 修复："一会一条线一会两条线" + 帧节奏

### ① 波形线宽忽粗忽细（"蹦迪"的真正原因）

**根因**：上一版为了保住 R 尖峰，对**整条波形**都做了"取离基线最远的那个采样"。
对尖峰是对的，但对**平滑段是错的** —— 平滑段那几个采样几乎一样，"取最远的"等于取**局部最小/最大包络**，
窗口一滑动，选中的点就在相邻两行之间跳 → **线在 1px / 2px 之间变**，整条波看着就在"模模糊糊地抖"。

而且 `WaveNext()` 里也做了同样的峰值保持，等于错了两层。

**修法：min/max 抽取**（数字示波器/监护仪的标准做法）：

```
每一列  = 该列 N 个采样的 最小..最大
平滑段  min ≈ max   -> 只画一条细线         ✅ 不再忽粗忽细
尖峰那列 跨度很大    -> 完整高度, 幅度不丢   ✅ 不衰减
相邻列范围取并集     -> 陡沿不断口
```

同时把 `WaveNext()` 里的超采样峰值保持**整个删掉** —— 平滑只应该由列级 min/max 负责。

**验证**（12 帧，统计每列笔画高度）：

| 线宽 | 占比 |
|---|---|
| **1px 细线** | **92.1%** ✅ |
| 2px | 3.0% |
| 3px+（QRS 陡沿） | 4.9% |

### ② 帧节奏（"掉帧嫌疑"）

两个问题：

1. **`fps` 不知何时被改成 30 了** —— 30fps 的滚动本来就明显不如 60 顺。已改回 60。
2. **兜底判断用时间差不可靠**：`GetTickCount64` 的分辨率就是 ~15.6ms，跟帧间隔 16.67ms 咬得太近，
   偶尔会误判成"卡住了"而多补一帧 —— 两帧挤在一起就是一次可见的顿挫。
   **改成用高精度定时器自己的信号状态判断**（`WaitForSingleObject(hTimer, 0)`）：
   - 正常时主循环秒收信号 → 这里超时 → 跳过，**绝不重复推进**
   - 菜单/拖窗等模态循环里 → 信号躺着没人收 → 补一帧并重新武装
   
   （顺带修了方差公式除数写错导致算出负数、`sqrt` 出 `nan` 的问题。）

**新增 `snap = 1`（整数步进）** —— 这是让滚动"又匀又脆"的关键：

- 每帧推进量取整 = `round(速度 / 帧率)`，至少 1 像素
- 60fps 下 `speed = 60` 正好是 **1 像素/帧**，每帧位移完全相同
- 因为 `frac` 恒为 0，取景走**纯 memcpy**，字形**完全不插值** → 不会有"抗锯齿每帧微变"造成的糊和抖
- 文字和波形用同一个步长，**天然同步**

代价：实际速度会被取整到 fps 的整数倍。想要任意速度就把 `snap` 改 0，走真实时间 + 亚像素插值。

**`--bench` 实测**：

| 指标 | 数值 |
|---|---|
| 取景 | **0.004 ms**（整数步进 → 回到纯 memcpy） |
| 每帧合计 | **0.100 ms** |
| 实跑帧率 | **60.0 fps** |
| 帧间隔 | 平均 **16.67 ms**，最小 16.21，最大 17.17，**标准差 0.23 ms** |
| 明显掉帧 | **0 次** ✅ |

## 19. v1.0 修复：波形顿挫（这次是实测出来的）

前面几轮一直在"猜"，这次给程序加了帧轨迹记录（`vitals.exe --ftrace`，
把每帧的 QPC 时间戳和滚动位置写进 `ftrace.txt`，跑 6 秒自动退出好让缓冲落盘）。
一测就露馅了：

```

瞬时速度:   平均 60.05    最小 48.6     最大 81.51 px/s     ← ±35% 波动
每帧位移:   全部 1px                                      ← 位移是对的，但"每帧隔多久"不对
```

### 原因①：跨帧漂移补偿 → 平均对、每帧不匀

`ScheduleFrame()` 原来做的是**跨帧补偿**：这一帧晚了，下一帧就提前补回来。
**平均间隔确实对，但每帧忽长忽短** —— 而人眼跟踪移动线条，看的恰恰是**每帧间隔**。

改成**帧内补偿**：

```
等待时间 = 帧周期 - 本帧已耗时
=> 每帧总长恒等于周期, 又准又匀
```

效果立竿见影：

| | 修前 | 修后 |
|---|---|---|
| 帧间隔标准差 | 1.57 ms | **0.167 ms**（均匀 9.4 倍）|
| 瞬时速度区间 | 48.6 ~ 81.5 | **56.8 ~ 62.1** px/s |

### 原因②：QRS 在"1 列 / 2 列"之间闪

按列取 min/max 虽然保住了幅度，但一个 ~1 像素宽的尖峰**跨在两列之间时会被拆成两条矮线**，
正好落在列中间时又是**一条高线** —— 亚像素位置一变就在这两种形态之间翻。

改成**横向抗锯齿的折线渲染**：

```
1) 逐"子列"算纵向范围（子列 = 相邻采样之间的线段，比像素密 4 倍）
2) 每个像素列 = 它覆盖的 4 个子列的横向平均覆盖度
```

这样尖峰的宽度随亚像素位置**平滑变化**，而不是在 1 列/2 列之间跳。

**验证**（12 帧统计）：

| 笔画 | 占比 | 说明 |
|---|---|---|
| ≤2px 细线 | **96.3%** | 平滑段 |
| 3~4px | 2.0% | 陡沿 |
| >4px | 1.7% | QRS 尖峰 |

R 波最高点 12 帧**全部落在同一行，极差 0** ✅

## 20. v1.1 修复：整体严重掉帧 + 波形变细

### ① 严重掉帧 —— 上一版引入的 bug

**根因**：模态循环兜底逻辑是「看一眼高精度定时器有没有信号」，用的是

```c
WaitForSingleObject(g_hTimer, 0) == WAIT_OBJECT_0
```

但**自动复位定时器只要被 wait 到就会清除信号**。于是：

1. 兜底检查发现「有信号」，但判断「还没到 25ms，不用补帧」→ 跳过
2. **可信号已经被吃掉了** → 主循环再也等不到这一帧 → **这一帧永久丢失**

帧定时器 16.67ms、兜底 WM_TIMER 15.6ms，两者相位一直在漂，所以会**周期性地撞上** → 成片掉帧。

**修法**：换成**手动复位**定时器（`CREATE_WAITABLE_TIMER_MANUAL_RESET`）：
探测不消费信号，只有 `SetWaitableTimer` 才复位。这样「看一眼但不补帧」是**无副作用**的安全操作。

**验证**（`--ftrace` 跑两次各 6 秒）：

| | 修前 | 修后 |
|---|---|---|
| 超过 25ms 的帧 | 周期性出现 | **0 次** ✅ |
| 帧间隔标准差 | — | **0.19 ms** |

### ② 顺带把 60fps 校准到位

修完掉帧后实测只有 **58.8fps**（平均间隔 17.03ms）—— 定时器唤醒有 ~0.35ms 固定延迟。

第一次补偿写成了「用周期误差当补偿量」，那是**纯积分环**，会自己把自己抵消掉，收敛不到位。

改成**直接估计唤醒延迟**（外生量，补偿它环路才稳定）：

```
延迟 = 实测周期 − (上帧工作量 + 上帧等待时间)
等待 = 帧周期 − 本帧工作量 − 平滑后的延迟
```

| | 修前 | 修后 |
|---|---|---|
| 实测帧率 | 58.8 fps | **59.97 fps** ✅ |
| 平均间隔 | 17.03 ms | **16.67 ms** ✅ |

### ③ 波形变细发虚

**根因**：抗锯齿那一版把每行的亮度按 `覆盖度 / 子列数` 算。平滑段每行往往只被 2~3 个子列覆盖，
于是整条线都只有 **~50% 亮度** → 看着又细又虚。

**修法**：改成按**本列的最大覆盖度**归一化 —— 主线那一行**永远满亮度**，只有边缘按比例淡出。

**验证**：有笔画的列里 **100% 是满亮度实心**、**0% 发虚** ✅

---

### 顺带一提：这几个 bug 都是"测出来"的

这轮全是靠 `--ftrace`（逐帧时间戳）和 `--bench`（帧间隔统计）定位的，没靠猜。
`--bench` 现在会直接打印「帧间隔最小/最大/标准差」和「超过 1.5 倍周期的掉帧次数」——
判断"卡不卡"就看这两行，比肉眼看靠谱得多。

## 21. v1.2 新增：波形粗细可调 `wave_bold`

抗锯齿那版之后波形只有 ~1.2px 宽，偏细。新增一个参数：

```ini
wave_bold = 1     ; 上下各往外扩几像素: 0=最细, 1~4 越来越粗
```

实现是**把每个子列的纵向范围上下各扩 N 像素**，所以尖峰也一起变粗（不像"画两遍"那样会造成重影）。
设置界面 → 波形 → **波形粗细** 里也有一根滑块。

实测平均笔画宽度：

| wave_bold | 平均宽度 | 观感 |
|---|---|---|
| 0 | 1.21 px | 细线 |
| **1**（默认）| **2.44 px** | **稍微加粗** |
| 2 | 3.66 px | 明显霓虹 |
| 3 | 4.89 px | 很粗 |

改成 `2` 会有更明显的赛博霓虹感；嫌糊就改回 `0`。

## 22. v1.3 修复：右键菜单期间掉帧

**现象**：右键面板 / 右键托盘图标时，动画明显变卡。

### 根因：模态循环里 `WM_TIMER` 靠不住

`TrackPopupMenu` 会跑一个**模态消息循环**，主循环的 `MsgWaitForMultipleObjectsEx` 收不到高精度定时器信号。
原本靠 `WM_TIMER` 兜底，但**实测下来不行**：

| 驱动方式 | 菜单期间平均帧间隔 |
|---|---|
| 什么都不做（冻结） | ∞ |
| `WM_TIMER` 兜底 | 26.9 ms（37fps），标准差 12.6ms，最大 92.7ms |
| 看门线程 + `WM_TIMER` 兜底 | 24.3 ms（41fps），标准差 7.3ms |

原因：**模态循环会把 `WM_TIMER` 大幅合并/丢弃**，靠它驱动不出 60fps。

### 修法：改用「投递消息」驱动

`PostMessage` 投出去的是**队列里的正式消息**，任何消息循环（包括模态循环）都必须派发 —— 这是关键区别。

所以加了一个**只负责投递的看门线程**：

```c
for (;;) {
    Sleep(4);
    if (主循环最近 30ms 内出过帧) continue;      // 正常时完全不插手
    if (队列里已有一条待处理) continue;          // 防止堆消息(见下)
    PostMessageW(hwnd, WM_FRAME, 0, 0);         // 只投递, 不画
}
```

- 线程里**只做 `PostMessage`**，所有 GDI 绘制仍然在主线程，不涉及跨线程画窗口
- 窗口收到 `WM_FRAME` 就 `ScrollTick(FrameDt())` —— 因为是**按真实流逝时间推进**，
  谁触发、触发几次都不影响速度，所以多投也没副作用

**投递频率 7.5ms**（比 16.7ms 高一倍）：实测 15.5ms 的投递间隔在模态循环里会被延迟到 24ms，
7.5ms 反而能让它稳定派发出来。

### 顺带堵了个隐患

高频投递会在长时间开着菜单时**堆积消息**，菜单关掉后一次性补帧会看到明显跳变。
所以加了「在途标记」：**同一时刻只允许一条 `WM_FRAME` 在队列里**（超过 150ms 没被处理就认为丢了，清掉重来）。

### 实测（`--ftrace`，菜单开关全程记录）

| 阶段 | 帧间隔 | 标准差 | 最大 |
|---|---|---|---|
| 菜单前 | 16.45 ms（61fps）| 1.79 ms | 17.21 ms |
| **菜单中** | **15.49 ms（64.6fps）** | **0.57 ms** | 17.88 ms |

菜单期间甚至比平时还稳 —— 因为看门线程的 7.5ms 投递比主循环的 16.7ms 更"密"，
模态循环能派发出来的帧反而更均匀。

## 23. v1.4 新增：圆角背景（渐变 / 毛玻璃 / 通透玻璃）

```ini
bg_style  = none     ; none / grad(黑灰渐变) / frost(毛玻璃) / glass(通透玻璃)
bg_radius = 40       ; 圆角半径(px), 会被钳到 窗口高/2 -> 就是四分之一个圆的胶囊端
bg_alpha  = 0        ; 背景透明度. 0 = 自动(渐变235 / 毛玻璃220 / 通透150)
```

设置界面 → 外观 → **背景样式 / 背景透明度 / 圆角半径** 也能调。

### 圆角：真的是四分之一个圆

半径会被钳到 `min(宽, 高) / 2`，所以给个大值（比如 40 对 52px 高的条）就直接是**胶囊**——
两端各一个完美的半圆。遮罩用 **4×4 超采样**算覆盖度，边缘是抗锯齿的，不会有锯齿。

> 实测验证：半径 45、窗口高 52 时，顶行的透明→不透明过渡点在 **x≈13**；
> 解析解 `26 - sqrt(26² - 22.5²) = 13.0` —— 完全吻合。

### 三种风格

| 风格 | 做法 |
|---|---|
| **grad 黑灰渐变** | 上 `#2A2E34` → 下 `#0B0D10` 的纵向渐变 |
| **glass 通透玻璃** | 冷色半透明（上 `#6E869A` → 下 `#22303 6`），默认透明度低，像蒙了一层玻璃 |
| **frost 毛玻璃** | **真的抓取窗口后面的桌面像素**，模糊后压暗 45% —— 见下 |

### 毛玻璃是怎么实现的（这段有点意思）

不能用 `UpdateLayeredWindow` + DWM 的 acrylic：ULW 的窗口内容是我们自己画的一整张位图，
DWM 的模糊背后没有东西可模糊。所以走**模拟**：

```
1. 把自己藏起来 (SWP_HIDEWINDOW)
2. DwmFlush()  ← 关键! 不等 DWM 真正合成掉, BitBlt 抓到的是黑屏
3. BitBlt 抓桌面那 (winW x winH) 一块
4. 立刻显示回来 (SWP_SHOWWINDOW)   ← 三步都在同一帧(<1ms)内, 看不到闪
5. 两趟可分离盒式模糊 (半径 7)
6. 压暗 45% 保证文字读得清
```

**踩的坑**：一开始漏了 `DwmFlush()`，抓到的是一片黑（实测横向标准差 0.51 ≈ 完全均匀，
颜色 #0D0D09）。加上之后标准差变 **3.11**（有真实的桌面纹理变化），颜色也变成了合理的暗棕。

还有两条保险：

- 抓完算一下平均亮度，**太黑就判定抓失败，自动退回黑灰渐变**（免得屏幕上出现一条黑条）
- 每 2 秒重抓一次（桌面上的东西可能变了），拖动窗口后立刻重抓

### 渲染管线变化

有背景样式时，行缓冲只装文字（透明底），`PaintWindow()` 从"整块 memcpy 覆盖"改成
**逐像素 source-over 叠加**，最后统一套圆角遮罩（连文字一起裁成胶囊形 —— 滚动内容进到圆角处就该被裁掉）。

没开背景样式时仍走原来的纯 memcpy 快路径，**性能一点没退**。
