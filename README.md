## 一、功能

### 显示
- **真·透明**：`UpdateLayeredWindow` + 预乘 alpha，不是 `SetLayeredWindowAttributes` 那种假透明，文字抗锯齿无黑边
- **跑马灯滚动**：整行无缝循环，速度/宽度/圈间距可调
- **中英混排统一**：一个字体通吃，中文宽度正好是英文的 **2 倍**（全角/半角），数字用固定像素格子右对齐
- **23 个数值槽**：肝功(ALT/AST/TBIL/ALB)、肾功(BUN/CREA/UA)、甲功(TSH/FT3/FT4)、血气(pH/PaO2/PaCO2/HCO3)、神经递质(DA/5-HT/NE)、生命体征(HR/RR/SpO2/T/BP)
- **每槽独立更新节奏**：心率 500ms 一动，肝功 60 秒才动一次，甲功 5 分钟 —— 才有监护仪的味道
- **超标箭头**：超出「正常区间」显示 ↑ / ↓ 并变报警色
- **实时波形**：ECG（P-QRS-T）/ PPG（脉搏波）/ RESP（呼吸波），节律由 HR/RR 驱动

### 交互
- 左键拖动 · 滚轮调字号 · 位置/字号自动记忆
- **托盘图标**：双击开设置，右键菜单（显示/隐藏、设置、波形开关、选设备、退出）
- **开机自启动**：写 `HKCU\...\Run`，无需管理员
- **设置界面**：仿 TrafficMonitor 的左侧分页 + 右侧自绘控件（滑块/开关/色板/分段选择），保存时**按 key 逐行改写 ini，保留你的注释**
- **监测设备界面**：28 个真实型号（Philips IntelliVue MX750 / GE CARESCAPE B650 / Huawei Watch D2 / Dexcom G7 / FLIR A700…），点一下切换信号源，再通过 `@DEVICE@` 显示在滚动条上

## 三、技术架构

### 渲染管线（三级缓冲）

```
① PaintLine()    整圈文字(文字+空隙) -> 行缓冲        ← 只在数值变化时重画(~0.36ms)
② PaintWindow()  按滚动偏移取一屏                     ← 每帧, 纯 memcpy 或亚像素插值
③ PaintWave()    波形画在窗口缓冲下方(不参与滚动)      ← 每帧, 子列抗锯齿
       ↓
   UpdateLayeredWindow()  ->  DWM 合成  ->  屏幕
```

**为什么快**：②里的"取景"之所以能是 `memcpy`，是因为①已经把**整圈**（文字 + 圈间空隙）都渲染进缓冲了，
取景只是切一段窗口出来，环绕处取模即可无缝衔接。

### 关键设计

| 问题 | 做法 |
|---|---|
| **GDI 画不了透明字** | GDI 往透明 DIB 上画字得到的是「alpha=0 的灰字」，叠上去什么都看不见。所以先在 scratch DIB 上**填不透明黑 + 画白字**得到「覆盖率图」，读 R 通道当 alpha，按颜色预乘叠回去。每槽独立颜色和 glitch 重影就是这么来的 |
| **数字位数变化导致滚动抖** | 每个槽按「它可能写出的最宽值」分配**固定像素格子**，数字在格子里右对齐 → 整行宽度恒定（跟字体是否等宽无关） |
| **中英字体不统一** | 判据是**中英宽度比 2:1**（全角/半角）。实测 DengXian/SimHei/SimSun = 2.00 ✅，YaHei = 1.64 ❌，Consolas **一个汉字字形都没有**。所以默认用单个中文字体通吃 |
| **帧率不稳** | `CreateWaitableTimerEx(CREATE_WAITABLE_TIMER_HIGH_RESOLUTION)` + `MsgWaitForMultipleObjectsEx` 自建游戏式主循环 |
| **菜单弹出时动画卡死** | `TrackPopupMenu` 是**模态消息循环**，主循环等不到高精度定时器信号。所以常态挂一个 16ms `WM_TIMER` 兜底（模态循环会正常派发它），并用**高精度定时器自己的信号状态 + QPC 时间差**双重判断，确保正常时绝不重复推进 |
| **每帧间隔不匀** | 帧内补偿：`等待 = 周期 − 本帧已耗时`。**不要用跨帧漂移补偿**（平均对但每帧忽长忽短，人眼一眼就看出来） |
| **1px 宽的尖峰会被平滑削掉** | 对尖峰做纵向插值 = 削幅度。改用**横向过采样 + 子列覆盖度平均**：采样点比像素密 4 倍，位置精度 0.25px，幅度天然守恒 |

## 六、踩过的坑（值得记一笔）

| 坑 | 现象 | 根因 |
|---|---|---|
| **txt 模式写 ini** | ini 打开只有一行，实测 **24469 个裸 CR** | 文本模式下 CRT 把 `\n` 翻译成 `\r\n`，而文件里本来就是 `\r\n` → `\r\r\n`，每保存一次多一层 |
| **"wb, ccs=UTF-8"** | 修上面那个时改的，结果更糟：文件变成 42 字节的 `x\0x\0` | **加了 `b` 之后 CRT 不认 `ccs` 参数**，宽字符流默认按 UTF-16LE 写出。必须用文本模式 |
| **`GetTickCount64` 当精确定时** | 动画偶尔"多走一步" | 它分辨率就是 15.6ms，和 16.7ms 的帧间隔挨太近，判断"卡没卡"会误判 |
| **峰值保持用错地方** | QRS 一帧高、一帧半高，像在蹦迪 | 对**整条**波形取"离基线最远的采样"，平滑段就变成了最小/最大**包络**；而 R 波只有 1px 宽，插值又会削幅度 |
| **混合两个字体** | 中英粗细/风格不统一 | 而且代码里数字用 `FW_SEMIBOLD`、中文用 `FW_NORMAL` —— 一混就不可能统一 |
| **测试脚本的坐标系** | 设置界面点击"没反应" | 测试进程是 DPI-unaware，`PostMessage` 的坐标被系统按 1.5 倍缩放后才到达；程序本身没问题（靠 `--setlog` 才找到） |

## 八、局限与后续方向

**已知局限**
- 数值全部是**模拟**的，不接真实数据
- 垂直任务栏（贴屏幕左右）未适配，会自动退化成水平布局
- 亚像素插值（`smooth=0` 的路子）会让小字号略微发软，所以默认用 `snap=1` 整数步进
- `snap=1` 时实际速度会被取整到帧率的整数倍（60fps → 60/120/180 px/s）

**可以继续做**
- 接真实数据源（串口 / HTTP / 文件监听）
- 多导联波形（II + V1 上下叠），或真监护仪那种「从左往右扫描」而不是滚动
- 嵌进任务栏本体（`SetParent` 到 `Shell_TrayWnd`，参考 TrafficMonitor）
- 每台设备绑定不同的指标组合（选 Watch D2 就只显示 HR/SpO2/BP）
- 用 `timeBeginPeriod` 或定时器队列替代部分逻辑，进一步降低唤醒抖动

## 九、怎么发到 GitHub

### 核心结论：exe 不进仓库，用 Releases 发

| 放哪 | 放什么 | 为什么 |
|---|---|---|
| **仓库** | 源码 + 配置模板 + 构建脚本 | 别人能编译、能看实现、能提 issue。Git 不适合存二进制 —— 每次改动都存一整份，仓库会迅速膨胀 |
| **Releases** | `vitals-win64.zip` | 普通用户下载解压就能用，不用装编译器 |

### 关于「只发一个 exe」

**从 v1.1 起可以了。** exe 里内置了一份默认 `vitals.ini`（RCDATA 资源），
**第一次运行会自动在 exe 旁边生成它**。

在此之前确实不行 —— 程序只会**读** ini，从来不会创建。所以单独一个 exe 跑起来用的是代码里的兜底默认值，
而且你想改配置连个文件都没有。

> 实现细节：`EnsureDefaultIni()` 用 `FindResource / LoadResource / LockResource` 从自己的资源段取出
> 那份 ini 写出去。注意写入路径不能用 `GetIniPath()` —— 那是**查找**函数（会兜底到 `%APPDATA%`），
> 要用 `GetModuleFileName` 拼出 exe 同目录。exe 目录不可写（比如装在 `Program Files`）时才退回 `%APPDATA%`。

### 具体步骤

1. **建仓库**，把这些传上去（`.gitignore` 会自动挡住 exe 和临时文件）：
   ```
   vitals.c  vitals.ini  vitals.rc  vitals.ico
   build.bat  pack.bat  make_icon.ps1
   .gitignore  README.md  CHANGELOG.md  CONTRIBUTING.md  LICENSE
   docs/DEVLOG.md  .github/workflows/build.yml  .editorconfig  .gitattributes
   ```
2. **打包**：双击 `pack.bat` → 生成 `dist\vitals-win64.zip`（约 190 KB）
3. **发 Release**：仓库页 → 右侧 `Releases` → `Draft a new release`
   - Tag：`v1.1.0`，Title：`vitals v1.1.0`
   - 把 `vitals-win64.zip` **拖到附件区**（不是提交进仓库）
   - `Publish release`
4. 别人下载 zip → 解压 → 双击 `vitals.exe`（ini 自动生成）
